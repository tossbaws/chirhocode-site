Server Sanctuary · by Chi Rho Code LLC

Your own game servers, on your own Linux machine.

Server Sanctuary is a terminal app (a TUI) that runs Valheim, Palworld and custom game servers on a Linux machine you control, with rootless Podman and systemd. It shows you what a change will do before it makes it: deployments, settings, bans and setup steps each get a review first.

In development: paid licences and downloads start with version 1.0.

See pricing Requirements and limits

What it is, and who it’s for

For you if…

  • you host a game for friends, family or a group on a Linux machine of your own: a home server, a spare PC or a server you rent;
  • you’re happy in a terminal and over SSH;
  • you’d rather see exactly what will change before it changes.

What it does

  • Checks the machine is ready (systemd, rootless Podman, Quadlet) and, on Ubuntu Server, offers each setup step for you to approve.
  • Runs each server as a rootless Podman container under a systemd user service, on its own ports, with its own world, settings and backups.
  • Starts, stops, backs up and removes servers from one screen, and shows real progress from systemd and the game’s own log lines.

What it isn’t

  • Not a hosting service: the servers run on your machine.
  • Not for Windows or macOS: Linux on x86_64 only.
  • Not a check that players can reach you: router port forwarding is up to you.

What every tier gets, Free included

Anything that keeps a single server safe and working is in every tier. Pro is for convenience once you run many servers; it never holds back the basics.

  • Crash restarts

    systemd restarts a server that fails, and brings your servers back after a reboot.

  • Game updates

    Each time a server starts, it checks Steam for a newer game build and installs it first.

  • Backups and scheduled backups

    World backups when you ask, or daily or weekly on a schedule, with a number to keep. A running server is stopped for a clean world save, then started again; while players are online it waits (up to 6 hours).

  • Every supported game

    Unmodded Valheim, unmodded Palworld, and custom game servers you describe in a TOML profile (a commented example for a Minecraft Bedrock server is included).

  • Stopped stays stopped

    A server you stop stays stopped, across reboots too, until you start it again.

  • Bans, the Log and scripts

    Ban and unban players on a server, see who is online and what happened in the Log, and drive it all from scripts with the headless commands.

The Free limit, in plain words

Free runs up to 2 game servers on each machine, on as many machines as you like, with no key.

If a machine has more than 2 servers and no valid licence (say, after a refund or more than 30 days offline), you get 24 hours’ warning. Then the 2 servers you pick, or the 2 oldest, keep running, and the others go on a licence hold: stopped cleanly with the world saved, and kept stopped. A held server is never deleted; you can still view it, read its log, back it up, ban players on it and remove it.

The hold lifts when the machine is licensed again or is down to 2 servers.

Download

Requirements and limits

You need

  • Linux on x86_64 with glibc 2.35 or newer.
  • systemd, with a user session; linger keeps servers running while you’re logged out.
  • Rootless Podman with Quadlet (Podman 4.4 or newer) and cgroup v2.
  • A regular user account, not root.
  • A terminal of at least 40×12 (100×24 or more shows the list and details side by side).
  • Enough memory for your games: each deployment is checked against the machine’s free memory first.

The Host check runs read-only checks for all of this. On Ubuntu Server it can install Podman and turn on linger, one step at a time after you approve each; your password goes to sudo, never to the app. On other distributions the checks are read-only and setup is up to you.

Limits, honestly

  • Linux on x86_64 only: no Windows, macOS or ARM builds.
  • Binaries aren’t code-signed; check them against SHA256SUMS.
  • No automatic updates of the app: you download each new version yourself.
  • It doesn’t check that players can reach your server, and it never changes your router or firewall.
  • Games: unmodded Valheim and Palworld, and custom profiles. No mods.
  • No Update Now button or update schedule: a game update is checked when a server starts.
  • Backups hold the world only, not the app’s own list of servers, and a restore brings back the world only. Backup and restore aren’t called production-ready yet; keep your own copy of anything you can’t lose.
  • The Ubuntu setup steps have run on Ubuntu Server 26.04.1 so far; 22.04 and 24.04 haven’t been tried yet.

What has run on a real host

All with pre-1.0 builds, October 2026.

  • On an Ubuntu VPS: deploy, first start, a player joining, a clean save on stop, the world kept across a restart, and removal.
  • On a test VM (Ubuntu Server 26.04.1, rootless Podman 5.7): Valheim and Palworld end to end with players joining on the local network, and their settings reaching both games.
  • Host reboots: servers saved cleanly on shutdown and came back at boot with nobody logged in; a server you stopped stayed stopped.
  • Bans enforced by both games; bulk settings across four servers; the Players screen with real joins.
  • A custom game server (the Minecraft Bedrock example) started and ran; a real player join on it is still unproven.
